Expand description

Represents a request to create a chat completion.

Fields§

§model: String

The identifier of the model to use for the completion (e.g., “gpt-4o”, “claude-sonnet-4”).

§messages: Vec<ChatMessage>

A list of messages that form the conversation history.

§temperature: Option<f32>

The sampling temperature to use, between 0.0 and 2.0. Higher values will make the output more random, while lower values will make it more focused and deterministic.

§max_tokens: Option<u32>

The maximum number of tokens to generate in the completion.

§max_completion_tokens: Option<u32>

Upper bound for completion tokens in modern OpenAI-compatible payloads.

§top_p: Option<f32>

The nucleus sampling parameter. The model considers the results of the tokens with top_p probability mass. So, 0.1 means only the tokens comprising the top 10% probability mass are considered.

§frequency_penalty: Option<f32>

A penalty applied to new tokens based on their frequency in the text so far. It decreases the model’s likelihood to repeat the same line verbatim.

§presence_penalty: Option<f32>

A penalty applied to new tokens based on whether they appear in the text so far. It increases the model’s likelihood to talk about new topics.

§stop: Option<StopSequences>

A list of sequences that will cause the model to stop generating further tokens.

§user: Option<String>

A unique identifier representing your end-user, which can help in monitoring and tracking conversations.

§provider: Option<ProviderOptions>

A hint to the router about which provider to use for the model.

§stream: Option<bool>

If set to true, the response will be streamed as a series of events.

§stream_options: Option<Value>

Stream behavior options (include_usage, etc.).

§cache_control: Option<Value>

Provider cache-control object forwarded by Rainy.

§logit_bias: Option<Value>

Modify the likelihood of specified tokens appearing in the completion.

§logprobs: Option<bool>

Whether to return log probabilities of the output tokens.

§top_logprobs: Option<u32>

An integer between 0 and 20 specifying the number of most likely tokens to return at each token position.

§n: Option<u32>

How many chat completion choices to generate for each input message.

§response_format: Option<ResponseFormat>

An object specifying the format that the model must output.

§tools: Option<Vec<Tool>>

A list of tools the model may call.

§tool_choice: Option<ToolChoice>

Controls which (if any) tool is called by the model.

§parallel_tool_calls: Option<bool>

Whether multiple tool calls may be emitted in parallel.

§seed: Option<i64>

Seed for deterministic sampling where supported.

§prompt_cache_key: Option<String>

Prompt cache key for provider routing/cache optimization.

§provider_options: Option<Value>

Provider-specific option bag.

§prompt_cache_retention: Option<String>

Prompt cache retention mode.

§reasoning: Option<ReasoningRequest>

Reasoning settings (bool/object depending on provider).

§reasoning_effort: Option<ReasoningEffort>

Top-level canonical reasoning-effort parameter.

§include_reasoning: Option<bool>

Include reasoning traces where supported.

§metadata: Option<HashMap<String, String>>

Arbitrary request metadata.

§service_tier: Option<String>

Requested service tier (auto, default, flex, etc.).

§store: Option<bool>

Persist request/response server-side when supported.

§safety_identifier: Option<String>

Stable identifier used by safety systems.

§modalities: Option<Vec<String>>

Requested output modalities.

§audio: Option<Value>

Audio generation options.

§prediction: Option<Value>

Prediction optimization payload.

§verbosity: Option<String>

Verbosity hint for some models.

§web_search_options: Option<Value>

Native web search options.

§image_config: Option<ChatImageConfig>

Image-generation controls used with modalities: ["image", ...].

§top_k: Option<f32>

Additional model-declared parameters such as top_k or min_p.

§min_p: Option<f32>

Minimum probability threshold when declared by the model.

§repetition_penalty: Option<f32>

Repetition penalty when declared by the model.

§structured_outputs: Option<bool>

Explicit structured-output compatibility flag.

§functions: Option<Vec<Value>>

Legacy functions field accepted by compat layers.

§function_call: Option<Value>

Legacy function-call directive accepted by compat layers.

§thinking_config: Option<ThinkingConfig>

Legacy in-memory thinking configuration. Use the modern reasoning fields; the builder maps this value to Rainy’s provider-neutral wire shape and does not serialize a hallucinated thinking_config field.

§extra: HashMap<String, Value>

Explicit extension fields for forward-compatible request parameters.
